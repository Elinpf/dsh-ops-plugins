# ADR-0006: 常驻策略（standing policy）——暂不实施，附威胁模型

- 日期：2026-08-28
- 状态：已决定（**暂不实施**；重提条件与所需证据见末节）
- 来源：ADR-0003/0004 缓议项；live-trial 票 11

## 背景

提议：让被信任的环境（如 test）长期放行 rw，agent 不必逐次申请审批。ADR-0004 当时的批注是「绕开『人一次性批准』原则，需独立威胁模型讨论——缓议」。本文档补上那场讨论。

## 决定

**暂不实施。** 票 07（grant 续期）今日刚上线，其吸收了多少 TTL 摩擦尚无使用数据；常驻策略的收益（省审批点击）与代价（下述三个维度全变）不成比例。重提条件不变：续期上线后仍感审批摩擦，且能拿出末节所列证据。

## 威胁模型分析：为什么这不是一个配置开关

### 审计语义

现行制度下每条 `rw-issue` 审计行都对应一次**活的授权**——时段、理由、批准人三要素齐全。「谁在何时为何动了写权限」有可定位的答案。常驻放行后 `rw-issue` 退化为「用了」而没有「为何此刻」：理由字段消失（没人再需要填），grant 账本失去审计锚点的意义，事故复盘从「读授权记录」退化为「猜」。

### 撤销面

现行撤销语义清晰且有两种粒度：立即收回（面板），或不再续期（TTL 自然收敛，分钟级）。常驻放行后撤销变成改配置 + 重载策略：已依据放行策略排好的一批操作如何处理？撤销动作本身要不要审计？它与票 12 的 deny 语义重叠但不等价——deny 是全锁，standing 撤销是「回到审批制」，状态机多一档。每一条都不是不能设计，而是必须设计——这正是「不是配置开关」的含义。

### 爆炸半径

现行误操作窗口 ≤ 一个 TTL（分钟级），且每个窗口有一次当刻的人确认。常驻放行后窗口 = 策略存续期（天/月级）：agent 幻觉、错误前提、提示注入在被放行环境获得**持久**写权限。「防犯傻不防作恶」模型的核心承重墙——写操作需要一次当下的人确认——被拆除。

### 收益核算（对照近日证据）

- 票 07 续期把 TTL 到期摩擦的主要部分吸收成「点一次延长」，而非重新走完整审批。
- 票 08 的实测结论：门控工具可靠时 agent 没有 bash 绕道动机——审批摩擦表现为点击次数，不是工作阻断。
- 常驻放行省下的只是「审批点击」这一下。对照上面三项结构性代价，收益不成比例。

## 若要重提，需要的证据

1. 续期上线后的真实审批数据：每天多少次批准/延长点击、打断的是哪类工作流；
2. 一个具体的常驻场景：哪个环境、什么工作模式、为什么续期（甚至更长 TTL 档位）不够；
3. 对三个威胁维度的新设计：审计锚点如何保留、撤销语义如何定义、误操作窗口如何收敛——写在 ADR 里再谈实施。

## 后果

- 无代码变更。票 11 关闭（决定即本文档）。ADR-0004 缓议表对应行更新。
