# ADR-0010: 具名 token 的精细化管理面（Web UI / PATCH API / CLI）

- 状态:已接受(已实现 —— `PATCH /tokens/:id`、CLI `token update`、Web UI 名册控制栏与就地编辑;单测全绿)
- 日期:2026-09-18
- 背景会话:任务看板 `t-mu6b0xqf-pqvzxf`「access-hub webui 中对 token 的管理」

## 上下文

ADR-0009 给了具名 token 完整的生命周期(签发 / 按人吊销 / 审计归属),Web UI 也上了名册区块。但管理面只有"新建"和"吊销"两个动作,外加一行状态徽标:

- **改标签 / 角色 / 有效期只能"吊销重建"**:持有人得重新配置一次,而"给临时工延长到期""把某人从 read 提为 admin""标签写错了改一下"这类调整是日常操作;
- **状态看不出精细差别**:已过期的 token 在名册里渲染成"至 <时间>",和"还有三年到期"长得几乎一样;也没有任何筛选,几十条记录时找一个人靠肉眼;
- **改动无迹可查**:当时连 `token-update` 这个审计动作都还不存在。

## 决策

### 1. `PATCH /tokens/:id` 就地编辑活记录

admin 端点,body `{name?,role?,expiresAt?}`,改的是**标签 / 角色 / 有效期**,不是秘密:

- 字段**缺席** = 不改;`expiresAt: null` 或 `''` = **清除有效期**(回到长期有效)——"保持"与"清除"必须是两个可区分的值,这正是 `parseExpiresAtPatch` 存在的理由;
- 秘密不变:编辑不重签、不换明文、前缀与摘要原样,持有人无需重新配置;角色变更**下一个请求即生效**(认证每次按摘要重查记录);
- 到期时间只收**未来**时间(过去 = 400),想让一把钥匙立刻失效请用吊销——两者语义不同;
- 已吊销记录 409(终态,要换就重建);未知 id 404;活标签冲突 409;空补丁 400。

### 2. 状态四分,判定只有一处

`active` / `expiring`(≤ 7 天) / `expired` / `revoked`。判定收在 `tokens.ts` 的 `tokenStatus()`,CLI 与 Web UI 共用同一语义(UI 因单文件无构建链,内联一份等价 JS,并在测试里锁住)。`active` 与 `expiring` **都仍可认证**——拆开的价值是让人在持有人被锁死之前续期。

### 3. Web UI 名册升级为控制面

关键字搜索(标签 / 前缀 / 创建者)+ 状态筛选 + 角色筛选 + 计数汇总 + 逐行"编辑"对话框 + 到期时间本地化显示 + 状态徽标;审计视图把 `changes` 附在动作名后。

### 4. 审计记 actor + changes(字段名,非值)

`token-update` 行带 `actor`(谁改的)与 `changes: ['name','role','expiresAt']`(改了哪些字段)。`token-*` 行因此能回答"谁在什么时候动了谁的凭证",同时仍然不落摘要、不落明文、不落字段值。

### 5. 幂等无操作不落盘

补丁与现值一致时不重写文档、不写审计行,返回 `changes: []`。文档是**整篇重加密**,写放大是真实成本,而"点了保存但什么都没改"是常见误触。

### 6. 名册筛选在前端做

名册上限 `MAX_TOKENS = 200`,前端过滤足够;服务端加 `?status=` 只会多一份需要同步的状态,不是更精细。

## 被否决方案

| 方案 | 否决原因 |
|---|---|
| 用"吊销 + 重新签发"代替编辑 | 换秘密 = 让持有人重新配置;改错一个字母的标签不该有这个代价 |
| 允许编辑已吊销记录(复活) | 吊销是终态(ADR-0009),复活会让审计里的 REVOKED 变成可争议状态 |
| 允许把有效期设为过去(变相立即失效) | 那是吊销的语义;混用会让审计无法区分"到期"与"被收回" |
| 细粒度 RBAC(按 kind/tier 授权) | 那是授权层的事(gate 的 grant 账本,ADR-0001),不是认证层;ADR-0009 的边界不变 |
| 服务端筛选 / 分页 | 上限 200 条,前端过滤足够 |
| token 详情页 / 独立路由 | 单文件 UI 无路由,对话框够用 |
| `lastUsedAt` 使用时间戳 | 与 ADR-0009 同因:每次请求都要重写整篇加密文档 |

## 后果

- 新增:`PATCH /tokens/:id`、审计动作 `token-update`、审计行可选 `changes`、`tokens.ts` 的 `TokenStatus`/`Expiring`/`tokenStatus`/`TokenPatch`/`TokenChange`/`parseExpiresAtPatch`、store 的 `updateToken`、CLI `token update`(在线 `--url` / 离线 `--data-dir` 两种落点)。
- Web UI 名册区块增加控制栏与编辑对话框;审计视图显示 `changes`。
- 静态 bootstrap token 与 ADR-0009 的全部既有行为**零改动**——既有消费者(core / gate / ops-knowledge)继续用静态 read token 或已换发的具名 token。
- 明确不做(延续 ADR-0009):用户体系 / 登录、自助注册、明文找回、按 kind/tier 的细粒度 RBAC、token 轮换自动化。
